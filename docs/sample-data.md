# Sample data

The workbench ships a deterministic, synthetic dataset generated by `scripts/generate-seed.ts`
(`npm run seed:generate`; output committed under `src/seed/`). No real personal data is used.

- **Source** `legacy_crm.customers` (schema `source-v1`): 200 records, all values text.
- **Target** `customers` (schema `target-v1`): 8 pre-existing customers per workspace, created natively in the new system.
- **Maximum sample size:** 500 records per workspace (`MAX_SOURCE_RECORDS`).

## Designed issues

Sequence numbers are 1-based positions in `src/seed/source-customers.json`. Base records are 1–197; 198–200 are appended duplicates.
The machine-readable manifest is `src/seed/issues.json`, and `tests/unit/seed.test.ts` checks the engine against it.

## Expected results with the reference plan

| Metric | Value |
|---|---|
| Source | 200 |
| Transformed (all rules succeeded) | 184 |
| Accepted | 177 |
| Rejected | 23 |
| — TRANSFORM_ERROR | 16 |
| — VALIDATION_ERROR | 3 |
| — DUPLICATE_SOURCE_KEY | 3 |
| — TARGET_CONFLICT | 1 |

The reference plan (`src/seed/reference-plan.ts`) is a hand-written correct answer used by tests, the mock LLM,
and as a yardstick for the agent. It reads ambiguous slash dates month-first; that is a business decision the
agent is expected to raise as a blocking clarification question.
